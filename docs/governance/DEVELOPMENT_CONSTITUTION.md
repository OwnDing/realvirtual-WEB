# realvirtual WEB 开发宪法

本文件是仓库的强制工程约束。Agent 入口见 [`../../AGENTS.md`](../../AGENTS.md)，安全细则见 [`AI_SAFETY.md`](AI_SAFETY.md)。违反 P0 规则的变更不得合并。

## 1. 产品与技术基线

realvirtual WEB 是开源、浏览器优先的工业数字孪生运行与创作平台：

- 3D 和渲染：Three.js，WebGL 为默认路径，WebGPU/WebXR 为受支持扩展路径；
- UI：React + MUI；
- 工业数据：SignalStore 与 WebSocket/MQTT/ctrlX/TwinCAT HMI 等接口；
- 仿真：固定时间步、连续物料流和 DES；
- 创作：项目文档、设备库、Layout Planner、Snap Point、信号绑定和脚本；
- 扩展：插件、事件、注册表、UI Slot、每模型代码包；
- AI：MCP/调试接口用于检查、操作和验证运行中的场景。

版本号、依赖、分支、远程仓库和私有扩展是否存在都属于易漂移事实，必须按 [`REPOSITORY_FACTS.md`](REPOSITORY_FACTS.md) 现场验证。

## 2. 数据与状态所有权

不同状态必须有唯一、清晰的权威来源，禁止为了方便把所有内容塞进 GLB 或全局存储。

| 状态 | 权威来源 | 约束 |
| --- | --- | --- |
| 设备固有几何、组件、端口和行为元数据 | GLB + `rv_extras`/rv-ODT | Schema 优先；兼容性变化必须迁移和回归 |
| 项目拥有的设备实例、变换、连接和覆盖 | 项目文档、操作日志和持久化后端 | 不得回写或污染只读库资产 |
| 部署功能、默认模型、网关和品牌 | 部署配置 | 必须有运行时校验和明确优先级 |
| 用户语言、布局和个人偏好 | 用户/浏览器偏好存储 | 不得成为共享项目业务事实 |
| PLC、传感器、告警和实时遥测 | 工业接口和运行时信号源 | 按方向与写权限处理，不得伪造持久状态 |
| 生成文档和工具清单 | 代码装饰器/Schema/生成脚本 | 修改生成源，禁止直接改生成围栏 |

改变任何状态所有权都必须先通过 ADR。

## 3. 架构铁律

| 编号 | 规则 |
| --- | --- |
| AR-1 | `src/core/engine/**` 不得依赖 `rv-viewer` 或插件门面；现有 ESLint 边界必须保持失败关闭。 |
| AR-2 | 跨插件协作优先使用类型化事件、窄注册表或显式接口；不得为单一功能引入隐式全局耦合。 |
| AR-3 | 插件和编辑器功能必须具备对称生命周期：注册/注销、创建/释放、订阅/退订、模型加载/清理。 |
| AR-4 | `RVViewer`、`main.ts` 和大型插件是高风险编排层；新增能力优先下沉到可独立测试的模块，不把新领域逻辑继续堆入入口。 |
| AR-5 | 公共 AGPL 构建必须在没有私有 sibling 的情况下可安装、类型检查、测试和构建。 |
| AR-6 | 新能力不得静态依赖仅在私有路径存在的模块；可选能力必须有显式能力探测或公开 Stub 契约。 |
| AR-7 | 不得通过修改生成文件、构建产物或缓存绕过源代码和契约。 |

## 4. 标识、路径和兼容性铁律

| 编号 | 规则 |
| --- | --- |
| ID-1 | 节点名称和路径不是稳定身份；需要跨重命名存活的引用优先使用 NodeId/完整地址。 |
| ID-2 | 项目、文档、资产、放置实例和端口必须使用稳定 ID；展示文本和多语言标签不得承担身份职责。 |
| ID-3 | 现有 GLB、`rv_extras`、项目清单和已保存布局默认需要向后兼容；破坏性变更必须采用版本化迁移。 |
| ID-4 | 对只读外部/库资产不得静默盖章随机 ID、改名、重排层级或回写元数据。 |
| ID-5 | 未知字段默认保留；旧客户端保存新版本文档时不得静默删除不认识的字段。 |

## 5. 仿真与性能铁律

| 编号 | 规则 |
| --- | --- |
| RT-1 | 固定时间步、Tick 顺序、暂停原因和实时信号覆盖语义属于运行时契约，改变前必须有 ExecPlan、特征测试和 ADR。 |
| RT-2 | 高频循环不得无依据引入每帧对象分配、同步 I/O、React 状态更新或全场景遍历。 |
| RT-3 | 性能优化必须保留正确性、选择/高亮/拾取和资源释放；仅有 FPS 提升不能证明完成。 |
| RT-4 | DES 与连续仿真需要明确确定性、时间推进和快照语义；不得把二者实现细节混成隐式行为。 |

## 6. UI、多语言与可访问性铁律

| 编号 | 规则 |
| --- | --- |
| UI-1 | 新增用户可见文本不得继续散落硬编码；在正式 i18n 契约落地前，必须集中到可迁移字符串入口并登记临时策略。 |
| UI-2 | 翻译键必须稳定、与英文文本解耦；设备、节点、信号和端口 ID 不得本地化。 |
| UI-3 | Viewer/HMI/Planner/DES、桌面/移动、插件参与和 UI 可见性是不同维度，不能用一个布尔开关替代。 |
| UI-4 | 扩展功能必须保持现有 UX，除非产品规格明确改变；键盘、触摸、错误状态和可访问名称属于验收范围。 |

## 7. 工业连接与安全铁律

| 编号 | 规则 |
| --- | --- |
| IO-1 | PLCOutput/PLCInput 等方向语义必须保持与现有契约一致，不得仅按 UI 的“输入/输出”直觉重命名。 |
| IO-2 | 读操作和写操作必须在接口、MCP 工具和 UI 中可区分；写能力必须受显式权限和用户意图控制。 |
| IO-3 | 写超时不等于未执行，禁止自动重试非幂等写；必须通过状态读取、调用 ID 或审计证据确认结果。 |
| IO-4 | 测试默认使用仿真、Mock、fixture 或明确隔离的开发网关；真实设备验收必须单独记录环境、授权和人工监督。 |
| IO-5 | 密钥、连接令牌和客户地址不得进入仓库；浏览器端配置不得承载服务器私密信息。 |

## 8. 测试与诚实交付

- 不得删除、跳过、静音、放宽或改写断言来隐藏回归。
- 修复缺陷前应先建立能够失败的最小复现或特征测试；确实无法自动化时记录原因和人工证据。
- 类型检查、单元测试和构建通过不代表真实设备、工业网关、弱网、移动端、WebXR 或大型模型验收通过。
- Agent 必须区分“代码已实现”“自动化已验证”“人工已验证”“真实环境已验证”。
- 大范围重构不得与功能变更混在同一不可审查 Diff；先冻结行为，再迁移结构。

## 9. 非目标与决策闸口

以下事项在 Approved 产品规格或 ADR 之前不得自行引入：

- 全面重写现有 Viewer/Planner/持久化体系；
- 为未来假设拆分微前端、微服务或新的通用平台框架；
- 把浏览器本地项目直接升级为云端组织/租户/权限系统；
- 把名称约定一次性替换为破坏兼容的新格式；
- 默认连接、控制或上传真实工业设备和客户资产。

需要产品或架构决定的事项登记在 [`OPEN_DECISIONS.md`](OPEN_DECISIONS.md)。
