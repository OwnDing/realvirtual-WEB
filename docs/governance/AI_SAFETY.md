# AI Agent 安全规则

本文件约束任何使用本仓库的 Coding Agent。目标不是降低自动化程度，而是确保每一步都在用户授权、项目边界和可恢复范围内。

## 1. 授权边界

- “评审、分析、了解、给方案”默认只读；不得顺手实现、提交或发布。
- “实现、修复、完成”允许修改任务范围内的仓库文件并运行适用验证，不自动授权提交、推送、部署或外部写操作。
- “提交”“推送”“发布”“部署”“控制设备”是彼此独立的授权，不能互相推导。
- 缺少会实质改变产品结果的用户决策时，停止相关分支并登记到 `OPEN_DECISIONS.md` 或询问用户。

## 2. 文件与 Git 安全

- 修改前运行 `git status --short --branch`，用户已有改动默认不可覆盖。
- 只修改任务允许的路径；临时文件放入明确的临时目录，不放在仓库根目录或用户目录。
- 禁止 `git reset --hard`、`git clean -fdx`、宽泛 checkout/restore、递归删除仓库根或未验证变量展开后的路径。
- 删除前必须列出精确目标、确认文件类型和作用域；优先采用可恢复操作。
- 未经明确要求，不创建提交、不改写历史、不变基、不推送、不创建 Release。
- 分支、remote、工作树和上游关系必须现场读取，不得从文档或旧会话猜测。
- `.claude/settings.json` 的 deny 规则是 Claude Code 运行时纵深防御，由 Governance Harness 校验；它不替代本文件，也不代表其他 Agent 自动具备同样限制。

## 3. 进程与开发服务器安全

- 禁止 `killall node`、`pkill node`、`taskkill /IM node.exe` 等全局进程清理。
- 端口被占用时先识别监听者；只能停止本次任务创建且 PID 已记录的进程。
- 不得为了释放端口终止其他仓库、用户应用、CONNECT、数据库或 IDE 进程。
- Agent 启动的长运行进程必须记录命令、工作目录、端口和停止方式。
- Harness 不得静默安装依赖、升级包管理器或修改 lockfile。

## 4. 工业信号与物理设备安全

- 默认只读检查 Signal、Drive、Sensor、PLC、MQTT、WebSocket 和 CONNECT 状态。
- 写信号、Jog、Move、Force、Reset、下发程序或切换真实接口前，必须确认目标是仿真/测试环境或获得明确的真实设备授权。
- 对真实设备写入时，先确认设备、信号、方向、单位、范围、当前模式和急停/联锁条件；没有这些证据时不得执行。
- 不使用生产信号作为自动化测试夹具，不在无人监督情况下运行循环写入。
- 写操作后必须读回状态；不得仅凭 HTTP/WebSocket/MCP 返回成功就宣称设备已达到目标状态。

## 5. MCP、调试 API 与超时

- MCP 工具的 `readOnlyHint` 是协作提示，不是对被篡改浏览器的安全边界。
- 对任何写工具，超时、断连或客户端错误都视为 `outcome unknown`，不得自动重试；先通过只读工具、场景快照或审计记录确认。
- 工具发现清单和生成文档必须同步；新增/修改工具后运行生成与漂移测试。
- 调试 API 只能用于明确的本地/测试目标；不得把公开或生产 URL 默认视为安全沙箱。
- 截图、日志和 Agent 报告不得包含密钥、客户模型、人员信息或生产网络详情。

## 6. 网络、依赖与外部系统

- 搜索和下载是读操作；上传、评论、发消息、创建 Issue/PR、修改云配置属于外部写操作，需要任务授权。
- 引入依赖前检查必要性、许可证、浏览器体积、运行权限和维护状态；必须通过 ExecPlan/ADR 记录跨领域影响。
- 不执行来源不明的安装脚本，不把网页命令直接复制到 Shell。
- 不在命令行参数、日志或文档中回显 Secret；发现疑似 Secret 时停止传播并报告路径，不打印值。

## 7. 测试与完成声明

- 不修改测试去迎合错误实现；需求变化时必须同步 Approved 规格和验收依据。
- 不把 Stub、Mock、私有模块缺席时的 no-op 路径说成真实集成完成。
- 无法运行的门禁必须说明原因、影响和剩余验证，不得写成“预计通过”。
- 真实 PLC、设备、跨浏览器、移动端、WebXR、大模型性能和生产部署若未验证，最终报告必须明确列为未验证。
- Approved 文档复审超期只产生治理 warning；不得用机械日期失效替代 Owner 对内容、代码和运行证据的复核。

## 8. 事故处理

发生意外写入、删除、设备动作、推送或部署时：

1. 立即停止继续扩大影响；
2. 保留日志和当前状态，不进行掩盖性修复；
3. 告知用户精确目标、时间、动作和已知结果；
4. 仅在获得授权后执行回滚或补救；
5. 将可机器化的防复发规则加入 Harness、测试或安全文档。
