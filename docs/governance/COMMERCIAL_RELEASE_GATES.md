# 商业交付权利与履约证据登记

本表集中保存阶段 A 已发现的 **A-01–A-08**，不新增授权或豁免；约束来源为 [ADR-0021](../adr/ADR-0021-agpl-commercial-delivery.md)、ADR-0019 和既有 [阶段 A 台账](../delivery/snapshots/phase-a-2026-10-26/REMEDIATION.md)。阶段研究或决策关闭不使这些条目通过。当前 **未批准正式商业交付**。

2026-10-27 用户确认限定范围结案后，本表由 [OD-010](OPEN_DECISIONS.md) 持续跟踪。OD-009 和 EP-LEGAL-001 关闭只接收定性与现有范围清点；下表八项仍 open，后续相关计划必须引用本登记并提交逐项证据。

每条关闭需写明具体版本/工件摘要、接收证据、审核角色与日期。未回答的事实记为“未确认”；没有许可正文证明不直接判作侵权，发现许可证也不自动判作履约。角色由项目负责人落实到实际人员，Agent 不代签。

## 后续工作的顺序

1. Product 提供事实：签约/交付主体、贡献与雇佣/委托关系、历史交付是否存在、首发精确范围。只在适当私密渠道保存敏感合同，仓库登记非敏感证据编号。
2. 按已选 AGPL 路线准备署名与源码交付的实施计划，并确认素材/CONNECT/CAD 的首发范围。允许前期设计及证据整理；本表不授权超出已批准计划的代码改动。
3. 实施并验证 A-01/A-02；供应链与 Appliance 任务接收 A-05/A-06/A-07，按确切制品完成内部清单和履约。关 UI 或标成 devDependency 不能证明组件未分发。
4. 对 A-03/A-04/A-08 完成事实与权利复核，再按最终工件签收各项并由产品负责人批准发布。获得 AGPL 许可不要求额外上游“同意函”；确有独立权利缺口时须取得相应证据。
