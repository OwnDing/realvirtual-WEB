# 多语言与本地化产品规格

## 1. 目的与状态

本规格定义 realvirtual WEB 首个多语言闭环的用户行为、边界和验收方向。OD-002 已关闭；在 i18n ADR 被接受且 `EP-I18N-001` 获批激活前，本文不单独授权安装框架、建立全局运行时或批量迁移 UI 文本。

## 2. 已确认的产品输入

| 项目 | 已确认内容 | 批准来源 |
| --- | --- | --- |
| 首批正式语言 | 中文、英文 | 2026-08-19 用户当前明确指令 |
| 默认语言 | 中文 | 2026-08-19 用户当前明确指令 |
| 规范 locale | `zh-CN`、`en-US` | 2026-08-19 用户确认进入下一步 |
| 回退链 | 当前语言 → `zh-CN` → 稳定 key 与可定位诊断 | 2026-08-19 用户确认进入下一步 |
| 翻译责任 | AI 直接完成英文翻译，不设置强制人工翻译/复核步骤 | 2026-08-19 用户当前明确指令 |
| locale 格式 | 日期和数字跟随当前 locale；工业单位、信号名称和稳定 ID 不本地化 | 2026-08-19 用户确认进入下一步 |
| 偏好所有权 | 用户/浏览器偏好，不属于共享项目事实 | `GOV-CONSTITUTION` 状态所有权 |

“默认中文”表示没有已保存语言偏好的新用户首先看到中文界面；用户主动选择其他已支持语言后，其个人偏好应优先于默认值。具体存储键、版本和优先级由后续契约定义。

## 3. AI 翻译与目录责任

- `zh-CN` 是产品源文案和最终回退目录；`en-US` 由 AI 直接翻译并作为版本化静态目录提交。
- AI 翻译发生在开发/维护流程，不在用户浏览器运行时调用外部 AI 服务；离线启动和语言切换不得依赖网络、令牌或第三方可用性。
- 不设置强制人工翻译或语言审校步骤。翻译进入产品前必须通过 key 集合、占位符、富文本标记、空值、重复项和目录漂移等机器检查，以及黄金切片行为验证。
- 工业术语表属于 AI 翻译约束；发现用词问题时更新源文案、术语约束或目标目录并保留普通代码评审历史。
- `zh`/`zh-*` 归一化为 `zh-CN`，`en`/`en-*` 归一化为 `en-US`；无法识别或没有已保存偏好的值使用 `zh-CN`。

运行时不得把源文案发送到外部翻译 API，也不得把 AI 输出绕过机器门禁直接视为功能完成。

## 4. 目标用户行为

1. 新用户在没有已保存偏好时以中文启动。
2. 用户可以在运行时于中文和英文之间切换；黄金切片不得要求重新导入模型或重新创建项目。
3. 用户选择的语言在刷新和重新打开应用后恢复，并且不会写入共享项目文档或 GLB。
4. 缺失翻译不得显示空白、`undefined` 或破坏交互；先回退到 `zh-CN`，源目录仍缺失时显示稳定 key 并产生可定位诊断。
5. 语言切换只改变展示文本和 locale 格式，不改变设备、节点、信号、端口、项目文档和资产的稳定 ID。
6. 桌面、触摸、键盘和可访问名称在黄金切片中保持可用；中英文长度变化不得遮挡关键操作。

## 5. 黄金切片范围

黄金切片应覆盖一个包含导航、动作、状态、错误消息和可访问名称的代表性 Planner/HMI 流程。具体页面在计划激活前根据字符串盘点选择，并要求：

- 中文默认启动；
- 切换英文后目标流程文本完整更新；
- 刷新后恢复用户选择；
- 至少一个英文缺失翻译反例回退到中文，一个源目录缺失反例显示稳定 key 并产生诊断；
- 保存项目、重新加载模型后稳定 ID 和业务数据不变。

## 6. Non-goals

- 不本地化设备、节点、信号、端口、文档路径或其他稳定身份；
- 不自动翻译用户项目内容、客户模型文本或工业信号名称；
- 不在浏览器运行时调用 AI 或翻译服务；
- 不在黄金切片通过前一次迁移全部 Viewer/HMI/Planner/DES 文本；
- 不由本产品规格直接选择 i18n 框架或改变用户偏好状态所有权；框架由 ADR 决定。

## 7. 验收方向

| 场景 | 预期 |
| --- | --- |
| 无已保存偏好首次启动 | 界面以中文显示 |
| 主动切换英文 | 黄金切片内所有受管文本和可访问名称切换为英文 |
| 刷新/重新打开 | 恢复用户上次选择的语言 |
| 英文翻译缺失 | 回退到 `zh-CN` 并产生可定位证据 |
| 中文源文案缺失 | 显示稳定 key 并产生可定位诊断，不显示空白或 `undefined` |
| 保存与重载项目 | 语言偏好不污染项目数据，稳定 ID 和业务内容不变 |
| 长文本与交互 | 中文、英文下关键按钮、错误和状态均可见且可操作 |

自动化映射和实际 Browser 证据将在 `EP-I18N-001` 激活后写入全局验收矩阵。

## 8. 依赖与下一决策
