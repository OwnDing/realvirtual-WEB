# 统一分层配置

## 1. 目标

同一份产品构建通过部署快照、项目配置、用户偏好与会话请求交付不同客户，不再为品牌、默认语言、工作区与功能开关维护客户源码 fork。每个有效值都可解释其来源，旧配置可自动迁移或安全忽略。

## 2. 用户可观察行为

1. 普通值按 `内置 < 部署默认 < 项目默认 < 用户偏好 < 会话请求` 解析。
2. 部署/组织策略在普通值解析后执行；锁定、能力缺失、工作区上限和功能拒绝不可被项目、用户、模型、文档或 URL 放宽。
3. 默认语言、默认/可用工作区和运行时功能开关不改代码即可配置。
4. 配置错误不会阻止基础 Viewer 启动；错误字段被忽略并产生不含敏感信息的诊断。安全字段继续失败关闭。
5. 诊断可展示每个字段的最终值、来源以及被策略拒绝的覆盖，不显示令牌、客户地址或工业数据。
6. 客户差异由交付 profile、品牌资源和离线许可证表达；不得以客户源码分支表达。

## 3. 状态所有权

- 部署快照拥有身份、法律、服务、外呼、安全上限、默认值和策略；组织平台在服务器侧生成该快照，L1 不提供浏览器组织策略编辑器。
- 项目配置拥有协作者共享的项目默认值和按稳定文档/模型 ID 选择的 profile；profile 不能修改安全字段。
- 用户配置拥有用户选择，并可按全局或项目 scope 保存；不得写回项目。
- 会话配置只来自明确 allowlist 的 URL/嵌入参数，不持久化。
- 文档和模型不是独立通用层；它们只能选择项目定义的 `modelProfiles`，并继续按既有 GLB/`rv_extras` 契约拥有工业事实。

## 4. 黄金切片

首个闭环覆盖：`locale`、`workspace.default`、`workspace.allowed`、`features.<stable-id>`，以及字段级来源/拒绝原因。身份、法律、外呼、服务和许可证沿用 `PS-CONFIG-001` 的部署专属最严格规则。

现有视觉、接口、搜索、分组、相机和多用户设置 bundle 继续兼容；项目自动加载改为内存默认值，不得污染用户 localStorage。将这些字段全部纳入类型化目录是后续扩展，不阻塞本黄金切片。

## 5. 迁移与兼容

- Deployment Config v1 自动投影为 v2 语义；未知未来版本忽略部署专属字段并保持默认拒绝外呼。
- `rv-settings-bundle/1.0` 继续用于用户显式导入/导出；作为项目/模型 sidecar 自动加载时只形成内存 overlay。
- 旧语言、工作区和插件覆盖 key 采用读旧写新并在一个兼容周期内双写旧 key；迁移必须幂等。
- 不改变 GLB、`rv_extras`、NodeId、项目/文档/资产 ID、插件 ID 或已保存场景。

## 6. 验收

- 四层组合、锁定、deny、工作区交集、无效/未知版本和迁移都有正反例自动测试；
- 部署默认语言在 React mount 前生效，用户和会话选择按优先级生效；
- 禁止的工作区不显示且深链/恢复不能进入，禁止的功能不能被用户或 mode 重启；
- 打开含旧项目 settings 的项目不会改写用户偏好；切换/关闭项目清除项目 overlay；
- 客户交付生成 `settings.json` v2、品牌资源与离线服务说明，并通过现有综合门禁。
