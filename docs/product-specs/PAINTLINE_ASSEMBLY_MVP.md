# 可手工组装涂装线数字孪生 MVP

## 目的

初期目标是让用户不依赖预制完整 Demo，也能从 Library 选择模块，拖入场景、通过稳定端口吸附成一条闭合涂装线，运行载具和基础涂装行为，并在保存、重新打开后继续编辑和运行。

批准来源为用户 2026-08-22 当前明确指令：同意“Library 可见、真实手工装配黄金流程、稳定端口契约、最小模块库、数据驱动行为”五项建议，并要求编写 ExecPlan 后完成。

## 用户闭环

1. 用户进入 Planner 即能看到本部署明确配置的涂装线 Library，不需要自己拼查询参数。
2. 用户可搜索并拖入直轨、弯轨、回转、工艺段、上下件、控制器和机器人模块。
3. 相容端口出现吸附反馈；类型或流向不兼容时不吸附，并给出可理解诊断。
4. 模块形成闭合路线后，控制器驱动挂具连续运行；开口、重复或不连通路线保持安全停止并显示无效状态。
5. 挂具经过上下件、前处理、喷涂、烘干、冷却和缓冲区时，基础状态、工件涂色及 KPI 根据模块元数据计算，不依赖 Demo 固定世界坐标。
6. 保存并重新打开场景后，设备布局、稳定端口寻址和可运行闭环恢复；用户可继续拖拽修改。

## MVP 模块

- 轨道：2 m / 4 m 直轨、90° 左/右弯、180° 回转；
- 工艺：上下件、前处理、喷房、烘干、冷却、缓冲/放行模块；
- 设备：涂装机器人、载具控制器；
- 既有完整悬挂链 Demo 作为参考资产保留，但不作为手工装配的唯一途径。

所有新增可连接模块必须符合 [`CONTRACT-ASSEMBLY-PORTS-001`](../contracts/ASSEMBLY_PORTS.md)。

## 运行与数据边界

- MVP 是浏览器内确定性仿真，不连接真实 PLC/MQTT，也不向外部设备写值。
- 运行态（载具瞬时位置、当前区段）不写回 GLB；布局和配置属于项目事实。
- 基础 KPI 至少包含装配有效、运行、线速、在制品、累计件数、已喷件数和估算每小时产量。
- 工艺行为使用模块组件元数据和拓扑，不用固定世界坐标或模型名称作为唯一身份。

## Non-goals

- 自动布线、碰撞规避和厂房级最优布局；
- 完整工艺配方、能耗、流体、烘烤曲线或真实质量预测；
- 多用户协同、云资产市场、权限与审计；
- 显式连接图持久化与复杂多分支调度；
- 真实 PLC/机器人控制或安全认证。

## 验收

| 场景 | 预期 |
| --- | --- |
| Planner 首次打开 | Library 显示明确配置的涂装线目录 |
| 拖放相容模块 | 放置成功并按端口吸附 |
| 类型/流向不相容 | 拒绝吸附，已有布局不被破坏 |
| 开口或断裂路线运行 | `AssemblyValid=false`，载具不运动 |
| 闭合路线运行 | 载具沿完整拓扑连续运行，工件经过喷房后变色 |
| 保存并重新打开 | 布局恢复、稳定端口可定位、路线可继续运行与编辑 |
| 旧资产/旧项目 | 旧 `Snap-*` 和 rv-ODT 1.0 继续可读 |

自动化至少覆盖一个真实浏览器黄金流程；GPU 画质、性能和真实设备行为若未验证必须单独披露。
