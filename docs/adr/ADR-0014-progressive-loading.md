# 派生性能包与会话自适应画质

## Context

完整 GLB 是当前加载、签名、业务元数据与保存的共同输入。已有字节进度仅在启动入口；批量渲染和拾取读取同一原始节点，必须保留这些契约。

## Decision

2026-10-08 用户批准会话方案。采用可选、版本化、带源 SHA-256 的派生性能包；预处理工具输出视觉资源及报告，原始文件不改写。预览不构造业务组件或执行脚本；最终原始 GLB 通过既有信任校验、组件和生命周期管线加载一次。LOD 视觉数据不能成为保存、碰撞或精确拾取依据。包摘要只证明一致性，不能赋予原模型或脚本信任。

共享加载会话拥有 AbortController、单调代次、阶段时间和只读快照。资源下载仍通过部署 egress，包内地址限定同源相对路径，取消后迟到结果释放。无包走原加载路径，坏包回退并显示诊断。清理对称且有资源上限。

自适应画质是用户明确可控的会话渲染覆盖层，独立于持久化视觉设置；使用活跃渲染采样和迟滞，用户手动调整撤销自动覆盖。不改变仿真所有权和 Tick。可恢复资源预算不是准确 VRAM 探测值。

## Alternatives

直接流读单 GLB 无法使当前 parseAsync 增量显示；仅添加 THREE.LOD 不提供网络调度。重写场景/持久化或将性能包作为业务权威会破坏兼容，不采用。

## Consequences

增加派生文件与预处理步骤；预览到完整场景存在短时资源重叠，须限制并释放。完整工业逻辑仍需原始模型可装入内存。预览画质与完整模型可能不同，界面清楚区分总览与完整就绪。

## Compatibility and Migration

不修改 GLB/rv-ODT、NodeId、项目格式、签名验证或单文件演示格式。新包完全可选；旧数据不需迁移。

## Validation

阶段状态机、取消竞态、长度未知、包版本/摘要/URL拒绝、LOD身份与释放、画质手动覆盖、真实浏览器首帧和基准验收。

## Rollback or Supersession

移除派生包并关闭会话画质即可回到普通加载；原始资产和保存文件不变。
