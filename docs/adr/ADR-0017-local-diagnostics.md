# ADR-0017：本地诊断采集与导出边界

## Context

用户于 2026-10-13 批准 L3-1 方案并要求执行。已有 500 条 rv-debug 日志、场景 ErrorStore、GPU/版本/加载接口；AI diagnose provider 与开发调试端点不适合作为生产诊断包服务。

## Decision

诊断模块拥有页面内存中的派生快照和最多 200 条异常/生命周期事件；复用结构化日志最多 500 条，不改变其调用契约。插件只通过现有事件/只读接口接入，启动层仅接线。采集、投影脱敏、导出分离；模块不依赖私有实现、不包含上传或工业写接口。控制台监听可组合、可释放且始终转交原调用。

白名单投影优先；任意日志 data 不导出，自由文本默认省略，栈只保留应用构建资源定位和行列号；明确维护的安全事件码表达关键故障。环境/GPU 字段只取已声明浏览器信息。导出和预览共用快照，名称不承担身份；不导出客户稳定 ID 或源名称。

ZIP 按需加载已有 jszip；失败用同版本 JSON。采集不跑 GPU benchmark、不新建工业连接、不作 OPFS 往返。场景遍历仅导出时分批进行，具备数量/时间限制、取消和代际校验。

启动异常捕获与 JSON 基础恢复使用独立可缓存的 `diagnostics-runtime` 构建块，与已有日志、告警、加载状态原语共用；告警/加载实例仍由 Viewer 持有，构建分块不改变状态所有权。设置面板和 ZIP 压缩依然按需加载。插件注入现有组件读取接口，使采集器不把场景注册表/Schema 携入诊断块。该拆分保证启动故障可诊断，不声称减少总启动下载量；同时检查原入口预算、新运行时大小及二者总量。

## Alternatives

远程 AI/调试端点需要额外服务并具有外发/写入语义；直接 dump 日志/项目会泄露客户数据；新增持久化日志需要迁移和保留政策。均未选用。

## Consequences

离线生产包可独立诊断。代价是历史有限、任意错误文本可能被省略、彻底崩溃无法恢复。不得把浏览器不可访问的信息宣称为已检测。

## Compatibility and Migration

只增加诊断产物格式 v1，无项目/GLB/配置迁移，不改变信号方向、仿真或原日志查询语义。

## Validation

见 [验收矩阵](../acceptance/DIAGNOSTIC_BUNDLE.md)：内容安全、下载解析、失败降级、无网络副作用、生命周期与公开生产构建。

## Rollback or Supersession

撤销新增诊断模块、UI 和启动接线即可，无持久数据回滚。跨刷新留存、远程合包或扩展敏感采集需要新决策。
