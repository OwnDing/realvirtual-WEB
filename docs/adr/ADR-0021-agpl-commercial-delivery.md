# ADR-0021：AGPL 商业交付与独立发行身份

## Context

用户于 2026-10-26 明确选择“接受 AGPL，允许客户取得源码并依法再分发”，并说明“没有授权书。主要面向中国大陆销售”。这就是本 ADR 商业路径决定的批准来源；后续“帮我关闭阶段A”不被解释为已取得律师意见、上游新授权或全部素材权利。

2026-10-27 用户对“定性与清点结案，法律与发布阻断保留”明确回复“确认”，批准阶段 A 的限定范围接收。OD-009 因路径与阶段范围决定落地而关闭；未决权利、法律签收与实际发布证据转入 OD-010，既有义务和八项未决状态不变。

代码基线为 `97f3936867f4f8db9dcaa543372dcc9723d74b57`，根许可 AGPL-3.0-only，schema 另为 CC-BY-4.0。研究依据及适用范围见 [备忘录](../references/COMMERCIALIZATION_PHASE_A.md)，路径清单与局限见 [取证快照](../delivery/snapshots/phase-a-2026-10-26/README.md)。仓库外 2026-08-24 draft 路线图中“AGPL 与商业收费冲突”“改品牌即可拿回所有权”的表述不作为本路线的前提。

## Decision

1. 采用 **AGPL-3.0-only 商业交付路线**，主要面向中国大陆；保留客户依适用许可取得对应源码、修改及再分发的权利。可对副本交付、实施、集成、定制、培训、维护等收费，不承诺受覆盖修改的闭源独占性，不以服务合同追加限制开源权利。
2. 本项目对外身份为基于 realvirtual WEB 的独立修改/发行及实施服务提供方。没有单独授权书时，不宣称官方代理、授权经销、独家合作、全部上游代码所有权或私有模块再分发权。AGPL 本身的许可与商业合作身份分别核实。
3. 保留原版权、适用法律通知及署名；自有品牌与上游署名可以并存。当前默认隐藏 attribution 的情况进入发布整改；本 ADR 不裁定历史条款效力，也不授权抹除通知。
4. 对应源码与适用网络取源义务按实际交付版本履行。版本、补丁、构建/安装材料、第三方声明与用户可访问入口必须有证据，不以默认分支链接或编译产物代替。独立客户数据与模型中的可执行程序分别判断，不能统一宣称全部 GLB 开源或全部 GLB 保密。
5. ADR-0007 的离线许可证继续是合同/服务凭证与审计机制；服务续期不得撤销客户已有的开源许可权。具体到期交互和客户合同仍须验证与本路线一致。本次不改运行时及其既有契约。
6. 原生库、容器、CONNECT、私有模块、字体、schema、示例和第三方素材逐项按自己的权利与义务处理。未知权利不视为授权，清单登记不等于可分发；实际交付范围由后续计划确定并验证。
7. ADR-0019 的供应链判定和例外机制保持不变。人工找到许可候选不自动清除技术失败，也不自动放行整个安装包。

## Alternatives

- 采购能覆盖闭源/限制再分发需要的其他许可：用户已接受 AGPL，因此本次不选择；将来改变路线时必须另核实完整授权范围。
- 继续把收费理解成禁止复制/修改/再分发的许可：与用户已选路径不符。
- 重写并主张全部自有：本次没有这项产品决定或证据，不据此投入或承诺。

## Consequences

后续配置、品牌、交付工程有了确定的许可方向，商业模式须接受客户依法再分发受覆盖软件。源码供应、署名和第三方义务进入持续交付成本。未确认的主体、贡献、历史履约、资产和独立组件权利仍需真实证据；本 ADR 不是专业法律意见或商业发布批准。

## Compatibility and Migration

不修改 LICENSE、CONTRIBUTING、代码、Schema、GLB/rv_extras、配置或保存格式。署名、源码包和最终制品整改须进入相应 ExecPlan，沿用现有兼容性规则。客户合同草案在完成主体与法律审阅前不得标作已审合同。

## Validation

产品决定可追溯到上述用户回复；法律分析可追溯到根 LICENSE 和引用的原始来源；清单按锁文件/制品摘要复核。发布前逐项关闭 [商业发布证据登记](../governance/COMMERCIAL_RELEASE_GATES.md)，包括正反例：有效源码包可获取/重建，缺源码或通知不可放行，未获权利素材不能因被打包而自动通过。治理校验只能验证文档一致性，不签发法律结论。

## Rollback or Supersession

通过后续批准的 ADR 改变未来商业路径；不能倒退撤回客户已经依法取得的 AGPL 权利，也不能用删除本文件改变第三方权属或既有协议。原始取证记录保持可追溯。
