# EP-LEGAL-001：商业化阶段 A

## Purpose

形成可供产品负责人、律师和上游审核的商业路径、权利边界与依赖证据包。区分工程取证完成、权利取得、法律意见签收和商业放行；后面三项不得由 Agent 推断完成。

## Scope

用户于 2026-10-26 明确要求“帮我完成阶段A”，授权本地取证、文档和必要分析。覆盖 AGPL 义务、上游关系、贡献权属线索、两份 npm 锁文件、原生/容器依赖、静态资源、内嵌库和已有交付配方。准备可审阅的律师任务书和上游询证函，均不发送。

2026-10-27 用户明确“确认”，接受“定性与清点结案，法律与发布阻断保留”。本计划按此范围完成：两份 npm 锁文件全覆盖，非 npm/资产完成已识别范围登记；不将其扩称为所有发布制品的完整内部 SBOM 或全部许可放行。原 M4 的外部权利、法律签收和实际履约转入 OD-010 及持续发布证据登记，保留 open。

## Non-goals

不修改产品代码、LICENSE、版权头、贡献协议、门禁策略或依赖版本；不购买许可、不代签合同、不联系第三方、不提交/推送/部署。用户后续已选择 AGPL；不凭该选择关闭剩余权属/履约/法律签收事项。不把网络公开条款当成覆盖历史版本的已签合同。

2026-10-28 用户追加“提交，推送，合并”，单独授权将本阶段仓库内交付物通过特性分支和 PR 合入 `develop`；覆盖上一段的 Git 交付限制。未授权部署、发送询证函、采购或变更发布门禁，阶段 A 的限定结案范围保持不变。

## Required Documents and Decisions

已读取开发宪法、AI 安全、文档优先级、文档中心、变更管理、完成定义、ExecPlan 模板与 OD 登记。遵循 ADR-0007 的合同凭证边界和 ADR-0019 的供应链证据边界；复用 EP-SEC-001 的清单工具，保持其未关闭项。阶段 A 路线与范围决定由 ADR-0021 落地、OD-009 关闭；未决权利和发布输入由 OD-010 接收。

## Surprises & Discoveries

- 当前 README/贡献协议混合 XYvirtual 品牌和上游商业许可主体，需审核适用性，不直接改写。
- 现有公共 npm 门禁不自动覆盖 mcp-bridge 独立锁文件、资产许可或 Appliance 中全部组件。
- 2026-10-22 的 100 条许可失败是历史扫描结论，本次重新采集，不沿用为当前合规判断。
- 本次 WEB 900、MCP bridge 186 条路径取证，合并为 997 个名称+版本；取证错误 0，原策略失败共 149 条。142 条缺正文路径对应 141 个版本，补得 122 个固定提交候选、5 个本地完整许可片段，14 个版本仍缺完整正文证明；补证不改原门禁。
- DefinitelyTyped 归档根可为 `node v20.19/`，原 inventory 仅识别 package/。本次分析工具用只读 tar 兼容非标准根并验证 manifest 身份，未修改公共扫描器或伪造 optional 标志。
- stackback 的 MIT 顶层声明之外含 V8 BSD 通知；PDF worker 与已安装 pdfjs-dist 字节相同；sharp-libvips 中另有 28 个组件，不能仅按 npm 顶层标签判断。
- 历史 b06e09a 的上游署名在当前默认品牌配置中不再可见，列为 A-01，不擅自改变运行时或把这一行为视为已获准。
