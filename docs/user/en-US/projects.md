# Saving, reopening and backup

## Prerequisites
Confirm that the current project is writable. Folder projects need browser folder permission. Browser projects belong to the current site and browser profile; they are not cloud synchronization.

## Steps
1. Open or create a project and check the name on the document card.
2. Use the document's save action after editing. Save read-only documents as project copies when prompted.
3. Wait for the save result, then close and reopen the same project to verify the changes.
4. Use the available project export/backup operation and retain the downloaded file. Back up complete folder-project directories according to IT procedures.
5. Test recovery on a separate copy. Follow the bundled upgrade procedure for backup and preflight before upgrading.

## Expected result
Reopening restores saved documents and changes. A `.demo.json` recipe contains camera shots and descriptions, not a project or model backup. Personal language and templates do not automatically become shared project data.

## Recovery
Reauthorize the correct folder after permission denial. For insufficient space, back up first and remove unrelated data; do not clear business site storage. For read-only targets, name conflicts, project changes or uncertain write outcomes, preserve current work and inspect the target before retrying. Changing browser, scheme, host or port can isolate local data. Export before migration.
