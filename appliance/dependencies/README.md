# Appliance dependency input

Formal appliance bundles are assembled from a target-specific dependency lock supplied to
`scripts/build-offline-appliance.mjs`. The dependency directory is already laid out as it will
appear below `runtime/` and `images/`; every ordinary file is declared separately in the lock.

The `locks/` directory contains dated, platform-specific OCI base locks resolved during release
validation. These are not portable across architectures and do not waive the requirement to
inspect the loaded image platform before building.

Required component ids are `node`, `caddy`, `connect`, `forgejo`, `influxdb`, `influx-cli`, and
`oci-images`; Windows additionally requires the `service-wrapper` WinSW binary. A native-only build may omit `oci-images`; a complete release generated by the
standard command contains both `native` and `container` modes.

```json
{
  "schemaVersion": 1,
  "target": "linux-x64",
  "components": [
    { "id": "node", "version": "22.22.2", "license": "MIT", "licenseFiles": ["licenses/third-party/node-MIT.txt"] },
    { "id": "caddy", "version": "2.x", "license": "Apache-2.0", "licenseFiles": ["licenses/third-party/caddy-Apache-2.0.txt"] }
  ],
  "files": [
    {
      "component": "node",
      "source": "node/bin/node",
      "destination": "runtime/node/bin/node",
      "bytes": 123,
      "sha256": "64 lowercase hex characters"
    }
  ]
}
```

Each component must supply at least one declared third-party license or notice file. The builder
also emits separate CycloneDX inventories for the production WEB dependencies and bundled
runtimes. The build refuses unknown paths, missing files, extra dependency files, wrong lengths, digest
mismatches, missing component ids, and test-fixture markers. There is deliberately no URL or
download fallback in this format.
